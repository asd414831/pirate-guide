多模组共存

玩家可以同时开很多模组。这章讲冲突时谁赢。

套用顺序

游戏开机时的顺序：

  1. 加载游戏本体的数据
  2. 依模组列表顺序，一个一个叠上去
后套用的赢 列表里比较后面的模组，会盖掉前面的。数据表、图片、音乐都是同一个规则。

什么情况叫冲突

类型冲突条件结果
数据表两个模组改同一个 Name 的同一个字段后面的值赢
图片两个模组放同路径同文件名的图后面的图赢
音乐两个模组放同文件名的音频文件后面的音频文件赢
改不同字段不会冲突 A 模组改药草的 SellPrice，B 模组改药草的 Desc —— 两个都会生效，因为合并只覆写“有写到的字段”。
这是模组兼容性比想像中好的主要原因。

玩家可以调顺序

模组管理页面可以手动排序。玩家遇到冲突时，可以把想要优先的模组排到后面。

所以“无法兼容”通常不是真的无法兼容 两个模组打架时，先请玩家试着调整顺序。真正无解的情况是 “两个模组都需要同一个字段是不同的值”。

给作者的建议

1. 改最少的字段

只写你真的要改的字段 想让道具卖贵一点，就只写 Name 和 SellPrice。
不要为了“完整”把整笔数据的所有字段都复制进来 —— 那会让你的模组跟每一个改同一笔数据的模组冲突，而且游戏更新后你的旧值会盖掉新的。

2. 新增内容用独特的名字

新增道具 / 角色 / 技能时，Name 建议加上自己的前缀：

"Name": "MyMod_超强药水"

这样不会意外撞到别人的新增内容，也不会撞到游戏未来新增的内容。

前缀只影响内部识别，玩家看不到 玩家看到的是 Name_I2，所以 Name 写多丑都没关系。

3. 图片和音乐也加前缀

Images/RoleHead/MyMod_NewHero.png
Music/BGM_MyMod_Theme.ogg

除非你刻意要覆盖本体或别人的素材，否则加前缀避免撞名。

4. 在 description 写清楚你改了什么

{
  "description": "改动：\n- 所有敌人 HP x2\n- 药草卖价 500\n\n会跟其他调整敌人数值的模组冲突。"
}

玩家才知道遇到问题时该关掉哪个。

模组不能互相依赖

没有“依赖”机制 你不能宣告“我的模组需要先装 XX 模组”。游戏不会检查，也不会提示。
如果你的模组真的依赖另一个模组的内容（例如引用了它新增的道具名）， 请在 description 里写清楚，并自行处理“对方没装”时的情况。

一个模组坏掉不会拖垮其他

错误是隔离的 某个模组的某个 JSON 档格式错误，只有那个文件被跳过。 同模组的其他文件、其他模组都正常运作。
所以玩家开了十个模组其中一个坏掉，游戏还是能玩 —— 只是那部分内容没生效。
