複数MODの共存

プレイヤーは多数のMODを同時に有効にできます。この章はどちらが勝つかの話です。

適用順序

  1. ゲーム本体のデータを読み込む
  2. MODを一覧の順に1つずつ重ねる
後のものが勝ちます 一覧で下にあるMODが上を上書きします。データ・画像・音声すべて同じルールです。

何が競合になるか

種類競合条件結果
データ2つのMODが同じ Name の同じ項目を変更後の値が勝つ
画像同じパス・同じファイル名後の画像が勝つ
音声同じファイル名後のファイルが勝つ
違う項目なら競合しません MOD Aが SellPrice、MOD Bが同じアイテムの Desc を変更 — 両方反映されます。マージは書かれた項目だけを上書きするからです。
MODの互換性が高いのは主にこの仕組みのおかげです。

プレイヤーが並び順を変えられます

MOD管理画面で手動並べ替えができます。競合したら優先したいものを下に移動。

「非互換」はたいてい本当の非互換ではありません まず並べ替えを試すよう伝えてください。解決不能なのは 「両方が同じ項目に別の値を必要とする」場合だけです。

作者向けの指針

1. 変更する項目は最小限に

本当に変えたい項目だけ書く 売値を上げたいなら Name と SellPrice だけ。
「完全を期して」全体をコピーすると、同じデータを触る全MODと競合し、 ゲーム更新後は古い値が新しい値を上書きしてしまいます。

2. 新規追加には独自の名前を

"Name": "MyMod_SuperPotion"
接頭辞は内部用で見えません プレイヤーが見るのは Name_I2 です。

3. 画像と音声にも接頭辞を

Images/RoleHead/MyMod_NewHero.png
Music/BGM_MyMod_Theme.ogg

意図的な差し替えでない限り接頭辞を付けてください。

4. 何を変えたか description に書く

{
  "description": "変更点：\n- 敵のHP 2倍\n- 薬草の売値 500\n\n敵の数値を調整する他のMODと競合します。"
}

MOD同士は依存できません

依存関係の仕組みはありません 「MOD XXが必要」と宣言できず、ゲームは検査も警告もしません。
依存する場合は description に明記し、 「入っていない場合」の挙動を自分で処理してください。

1つ壊れても他は巻き添えになりません

エラーは隔離されます 壊れたJSONはそのファイルだけスキップ。同じMODの他ファイルも、他のMODも正常に動きます。
