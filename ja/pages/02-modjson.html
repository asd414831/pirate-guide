mod.json の項目

MODの名刺ファイル。MOD一覧でプレイヤーに何が見えるかを決めます。

置き場所

Mods/<あなたのMODフォルダ>/mod.json
mod.json が無いとMODではありません Mods/ を走査する際、ゲームはmod.json を含むサブフォルダ だけをMODとみなします。無い場合そのフォルダは完全に無視され、一覧にも出ず、 エラーメッセージも出ません。

記入例

{
  "name": "高難度パイレーツ",
  "author": "とあるプレイヤー",
  "version": "1.2.0",
  "description": "敵が強化され、ドロップが渋くなります。\n2周目以降向け。",
  "icon": "icon.png"
}

項目一覧

項目型省略時説明
name文字列フォルダ名を使用 MOD一覧に表示される名前。言語は問いません。
author文字列「作者不明」と表示 あなたの名前かハンドル。
version文字列「-」と表示 表示専用。ゲームはバージョンの大小を比較しません。 1.0 でも v2-beta でも構いません。
description文字列空欄 説明文。改行は \n。
icon文字列icon.png サムネイルの相対パス。ファイルが無ければ既定画像になります。
すべての項目が省略可能です 空の {} でも動きます — フォルダ名が表示名になります。 項目を1つ書き忘れてもMODは壊れません。これは意図的な設計です。

サムネイル

既定ではMODフォルダ直下の icon.png を探します。別名やサブフォルダを使う場合：

{
  "icon": "art/my-thumbnail.png"
}

パスは Mods/ ではなくMODフォルダからの相対です。

改行の書き方

JSONの文字列に生の改行は入れられません。\n を使います：

{
  "description": "1行目\n2行目\n\n1行空けて3行目"
}
Windowsパスのバックスラッシュはエスケープが必要 JSONでは \ が特殊文字です。icon のパスには スラッシュを使ってください — art/icon.png であり、 art\icon.png ではありません。 バックスラッシュを書くなら2つ重ねる必要があり、間違いのもとです。

書式が壊れている場合

mod.json はあるが書式エラー（カンマ抜け、余分なカンマ、引用符の閉じ忘れ）が ある場合、MODは一覧に出ますが「壊れている」と表示されます。

これは意図的です 壊れたMODが黙って消えると、プレイヤーは「ファイルの置き場所が違うのか」と思い、 調べようがありません。一覧に出して印を付けることで「存在はするが問題がある」と分かります。

よくあるJSONのミス：

{
  "name": "私のMOD",
  "author": "誰か",     <-- 最後の項目に余分なカンマ
}

{
  "name": "私のMOD"
  "author": "誰か"      <-- 項目の間のカンマ抜け
}

{
  'name': '私のMOD'     <-- JSONは二重引用符のみ
}
VS Codeで編集すれば9割は防げます 入力中に書式エラーを指摘してくれます。あるいはオンラインのJSONバリデータに貼って確認を。

フォルダ名は変えない

有効状態はフォルダ名に紐づいています（name 項目ではありません） mod.json の name 変更：安全。表示名が変わるだけ。
フォルダ名の変更：ゲームから見れば別のMODになり、 有効状態がリセットされてプレイヤーが入れ直すことになります。公開後は変更しないでください。
