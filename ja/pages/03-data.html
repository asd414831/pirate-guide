ゲームデータの編集

MODの主な機能。既存の数値を変更する、あるいは新しい内容を追加する。

基本ルール

Mods/<あなたのMOD>/Data/<テーブル名>/<任意のファイル名>.json
  • フォルダ名で対象テーブルが決まる — Data/Item/ はアイテム、Data/Role/ はキャラクター
  • JSONファイル1つが1件 — アイテム1つにつきファイル1つ。複数を1ファイルに詰めないでください
  • ファイル名は無関係 — ゲームが見るのは中身の Name。 ファイル名は自分が分かりやすいようにするためだけのものです
Item でも TheItem でも通ります 内部のテーブル名は TheItem ですが、フォルダが Item のときは ゲームが自動で The を補います。両方受け付けるので、つまずく箇所が1つ減ります。

マージ規則（最重要）

ゲームには既にデータ一式があります。あなたのJSONはその上に重ねられるもので、 置き換えではありません。照合のキーは Name 項目です：

あなたの Name結果
ゲームに既にある名前 その場で変更。書いた項目だけが変わり、他はすべて元の値のまま
ゲームに無い名前 新規追加。リストの末尾に足される
変えたい項目だけ書けば済みます アイテムの売値を上げたいなら、ファイル全体が2行：
{ "Name": "薬草", "SellPrice": 500 }
他の項目（名前・アイコン・効果）は一切影響を受けません。
「削除」機能はありません MODはゲームの既存内容を消せません。何かを出さないようにしたい場合は、 UnlockCon に決して成立しない条件を設定してください。削除を試みてはいけません。

Name は識別子です

Name のタイプミスは「変更」を「追加」に変えます 「薬草」を変えるつもりで「薬苴」と書いた場合、ゲームはエラーを出さず 「薬苴」という新アイテムを追加したと解釈します。 結果：元の薬草は変わらず、変な新アイテムが増えます。
MODが効かないときはまず Name のタイプミスを疑ってください （余分な空白や全角半角の違いも含めて）。

項目名の調べ方

項目名はゲーム内部の名前と大文字小文字まで一致する必要があります。最も確実なのは 演出エディタのデータテーブル機能 （演出エディタ 参照）で、各テーブルの全項目が見られます。

わざと近い名前を書く手もあります 存在しない項目名を書くと、ゲームが候補を提示します：
TheItem に項目「IconImage」はありません。「IconName」ですか？
資料を探すより速いです。

新規追加には ID が必要

新規データの ID は 0 より大きくないとスキップされます ID が 0 以下のデータは表計算のプレースホルダ行とみなされ、ゲームに出ません。
9000 以上を推奨 — ゲーム本体が後から追加する内容との衝突を避けられます。
既存データを変更する場合は ID 不要です（元の値が保持されます）。

型：引用符が必要なとき

JSONは数値と文字列で書き方が違い、ゲームの項目型と一致させる必要があります。

{
  "Name": "SuperPotion",
  "SellPrice": 500,               数値、引用符なし
  "AddHP": 999,                   数値、引用符なし
  "Name_I2": "スーパーポーション",  文字列、引用符あり
  "Atk": "20"                     文字列、引用符あり（下記参照）
}
装備の能力値項目は数値ではなく「文字列」です Atk / MaxHP / AtkPercent といった項目には 計算式の文字列が入るため、"Atk": 20 ではなく "Atk": "20" と書きます。
これによりレベルに応じた数値変化が可能になっています。引用符が要るか迷ったら、 ゲーム本体の同種データがどう書かれているかを見て真似してください。

リスト型の項目

複数の値を持てる項目は、JSONでは配列で書きます：

{
  "Name": "あるキャラ",
  "Skill": ["斬撃", "強斬", "旋回斬"]
}
配列は「まるごと置き換え」で、追加ではありません こう書くとそのキャラのスキルはこの3つだけになり、元のものは消えます。
元のスキルを残して追加したいなら、元のものも一緒に並べてください。
なぜ追加方式にしないか：同じパッチが2回適用されると ["斬撃","強斬","斬撃","強斬"] になってしまいます。置き換えのほうが予測可能です。

カンマ区切りの項目

内部的に「カンマ区切りの1つの文字列」として保持される項目もあります （アイテムの Tag など）。どちらの書き方でも同じ意味です：

"Tag": "戦闘中使用可,果物"
"Tag": ["戦闘中使用可", "果物"]

例：既存アイテムの変更

Data/Item/HerbPrice.json

{
  "Name": "薬草",
  "SellPrice": 500
}

売値だけが変わり、他は何も変わりません。

例：アイテムの追加

Data/Item/SuperPotion.json

{
  "Name": "SuperPotion",
  "Name_I2": "スーパーポーション",
  "Desc": "飲むととても強くなる",
  "Type": "アイテム",
  "IconName": "Potion",
  "SellPrice": 1000,
  "AddHP": 999,
  "AddMP": 99
}
IconName はゲーム本体の画像を借りられます 既存アイコン名を書けばその画像が使われます。自作画像を使う場合は 画像の追加 を参照。

例：敵を強化する

Data/Enemy/SlimeBuff.json

{
  "Name": "スライム",
  "MaxHP": "200",
  "Atk": "30"
}

多言語対応

ゲームは繁体字中国語 / 簡体字中国語 / 英語 / 日本語 / 韓国語 / ロシア語に対応しています。 末尾が _I2 の名前・説明項目が翻訳システムに渡されます。

Name_I2 を書き忘れると名前が空欄になります Name は内部識別子にすぎず、プレイヤーが見るのは Name_I2 です。Name だけ書いた場合、 ゲーム内で名前も説明も空欄になり、エラーも出ません。
多言語対応をしない場合でも必ず Name_I2 を書いてください — 母語をそのまま入れれば十分です。
文字列の末尾に句読点を置かないでください 翻訳システムは末尾の句読点を区切り文字として扱うため、検索が失敗します。
"大ダメージを与える。" ではなく "大ダメージを与える" と書いてください。
文中の読点も半角スペースに置き換えるのが安全です。

適用順序

MODデータはゲーム起動時に適用されます：

  1. ゲームが自身のデータを読み込む
  2. MODが順番に重ねられる（後のMODが前のMODを上書き）

MODは常に最上層なので、あなたの変更は必ず反映されます。 MOD同士の競合については 複数MODの共存 を参照。

編集後はタイトルから入り直してください データは新規開始とセーブ読み込み時にマージされます。 タイトルに戻ってもう一度入るだけで反映され、 ゲームの再起動は不要です。進行中のセッションは変わりません。
