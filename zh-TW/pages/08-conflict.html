多模組共存

玩家可以同時開很多模組。這章講衝突時誰贏。

套用順序

遊戲開機時的順序：

  1. 載入遊戲本體的資料
  2. 依模組清單順序，一個一個疊上去
後套用的贏 清單裡比較後面的模組，會蓋掉前面的。資料表、圖片、音樂都是同一個規則。

什麼情況叫衝突

類型衝突條件結果
資料表兩個模組改同一個 Name 的同一個欄位後面的值贏
圖片兩個模組放同路徑同檔名的圖後面的圖贏
音樂兩個模組放同檔名的音檔後面的音檔贏
改不同欄位不會衝突 A 模組改藥草的 SellPrice，B 模組改藥草的 Desc —— 兩個都會生效，因為合併只覆寫「有寫到的欄位」。
這是模組相容性比想像中好的主要原因。

玩家可以調順序

模組管理頁面可以手動排序。玩家遇到衝突時，可以把想要優先的模組排到後面。

所以「無法相容」通常不是真的無法相容 兩個模組打架時，先請玩家試著調整順序。真正無解的情況是 「兩個模組都需要同一個欄位是不同的值」。

給作者的建議

1. 改最少的欄位

只寫你真的要改的欄位 想讓道具賣貴一點，就只寫 Name 和 SellPrice。
不要為了「完整」把整筆資料的所有欄位都複製進來 —— 那會讓你的模組跟每一個改同一筆資料的模組衝突，而且遊戲更新後你的舊值會蓋掉新的。

2. 新增內容用獨特的名字

新增道具 / 角色 / 技能時，Name 建議加上自己的前綴：

"Name": "MyMod_超強藥水"

這樣不會意外撞到別人的新增內容，也不會撞到遊戲未來新增的內容。

前綴只影響內部識別，玩家看不到 玩家看到的是 Name_I2，所以 Name 寫多醜都沒關係。

3. 圖片和音樂也加前綴

Images/RoleHead/MyMod_NewHero.png
Music/BGM_MyMod_Theme.ogg

除非你刻意要覆蓋本體或別人的素材，否則加前綴避免撞名。

4. 在 description 寫清楚你改了什麼

{
  "description": "改動：\n- 所有敵人 HP x2\n- 藥草賣價 500\n\n會跟其他調整敵人數值的模組衝突。"
}

玩家才知道遇到問題時該關掉哪個。

模組不能互相依賴

沒有「依賴」機制 你不能宣告「我的模組需要先裝 XX 模組」。遊戲不會檢查，也不會提示。
如果你的模組真的依賴另一個模組的內容（例如引用了它新增的道具名）， 請在 description 裡寫清楚，並自行處理「對方沒裝」時的情況。

一個模組壞掉不會拖垮其他

錯誤是隔離的 某個模組的某個 JSON 檔格式錯誤，只有那個檔案被跳過。 同模組的其他檔案、其他模組都正常運作。
所以玩家開了十個模組其中一個壞掉，遊戲還是能玩 —— 只是那部分內容沒生效。
