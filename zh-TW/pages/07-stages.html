關卡與敵人

做一整套自己的戰鬥內容。敵人、AI、波次、背景、劇情。

敵人

Data/Enemy/Emma.json

{
  "Name": "艾瑪",
  "ID": 9201,
  "PSB": "Emma,Normal,Normal",
  "WellTerrain": "洞窟",
  "StartHP": 420, "LvAddHP": 18,
  "StartAtk": 48, "LvAddAtk": 1,
  "Pos_y": -1120, "Sca": 48,
  "DoID":    ["1",          "1",           "1"],
  "DoCON":   ["",           "{Turn}%4==3", "{Turn}%3==0"],
  "DoSkill": ["連環普通拳", "急速療癒",    "防禦"]
}

敵人 AI：三條平行清單

DoID / DoCON / DoSkill 是對齊的三條清單。同一個位置是同一條規則。

欄位意義
DoID權重。數字越大越常被抽中。填 -1 = 開場被動（該格 DoSkill 必須是被動技能）
DoCON發動條件。空字串 = 永遠成立
DoSkill技能名。要對得上遊戲既有的，或你自己在 Data/Skill/ 加的
三條長度不一致時以最短的為準 多出來的會被安靜忽略，不會報錯。要自己數好。

上面的範例讀起來是：

  • 平常用「連環普通拳」
  • 第 3、7、11… 回合用「急速療癒」（{Turn}%4==3）
  • 第 3、6、9… 回合用「防禦」（{Turn}%3==0）

敵人立繪的位置與大小

欄位說明
Pos_y立繪在戰鬥畫面的垂直位置。雜魚大多在 -1120 附近
Sca縮放。雜魚大多在 70～80
Sca 要配合你那張 PNG 的實際像素高度 圖越高，Sca 要越小。
範例的艾瑪原圖是 1475×2020，所以 Sca 用 48。
同樣的畫面高度換成 1000×1600 的圖，就要填 60 左右。
最快的做法：抄一隻體型相近的既有敵人 找遊戲裡大小差不多的敵人，把它的 Pos_y / Sca 抄過來再微調。
調整立繪不用重開遊戲 改完存檔，回標題重新「開始新遊戲」或「讀取存檔」就會套用。

跟角色完全同一套規則（見加入圖片）， 差別只在敵人的欄位叫 PSB。

PSB 的三段是「PSB名,表情,服裝」：

關卡

Data/Stage/AbyssTrial.json

{
  "Name": "模組試煉 深淵",
  "ID": 9201,
  "Group": "模組",
  "Tag": "戰鬥",
  "Rank": 1,
  "FightWinExp": "60", "FightWinMoney": "60",
  "FightWhere": "洞窟",
  "FightBackground": "Background_ModAbyss, Background_ModAbyss_Night",
  "FightBGM": "BGM_Fight2",
  "EnemyLv": ["3", "5"],
  "Enemys":  ["艾瑪", "艾瑪, 幽靈水母"],
  "GetItem": ["蘋果"],
  "GetItemProbability": ["0.5"]
}
欄位說明
Group關卡選單的群組。遊戲內建了一個叫「模組」的群組可以直接用
Tag沒有「戰鬥」的話只播演出、不開戰
FightWhere場地，影響地形相性
FightBackground戰鬥背景。逗號分隔可以每波換一張
FightBGM戰鬥音樂。逗號分隔可以每波換一首

波次

Enemys 的一個元素 = 一個波次 同一波要出多隻時用逗號隔開。 
"Enemys": ["艾瑪", "艾瑪, 幽靈水母"]     第一波 1 隻、第二波 2 隻
"Enemys": ["艾瑪,幽靈水母"]              一波 2 隻（空格有沒有都認得）
敵人可以直接用遊戲既有的 上面的「幽靈水母」就是遊戲本體的敵人，不一定要自己新增。
同一波不要放兩隻同名的敵人 不要寫 "艾瑪, 艾瑪"。
遊戲有不少地方是用名字回查敵人在場上的位置， 兩隻同名時永遠只查得到第一隻 —— 第二隻的特效座標和目標鎖定會跑到第一隻身上。
想讓同款敵人出兩隻，複製一份資料改個名字 （遊戲本體的「騎士 / 騎士B / 騎士C」就是這樣做的）。
跨波次同名沒問題（每波開始前會整批清掉重生）。

平行對齊的清單

這些欄位是「一個元素一個波次」或「同位置是同一項」：

欄位組對齊方式
Enemys / EnemyLv一個元素 = 一個波次
FightBackground / FightBGM逗號分隔，一個 = 一個波次
GetItem / GetItemProbability同位置 = 同一項掉落
清單比波數短時會自動沿用 EnemyLv 不夠長時遊戲會自動算等級； FightBackground / FightBGM 不夠時沿用第一個。

關卡劇情

三個欄位可以掛演出，值就是演出的 Name：

欄位時機
StartShow進關卡、開打之前
FightWinShow打贏之後
FightLoseShow打輸之後

三個都是選填，留空就沒有那段演出。演出本身放在 Data/Show/ （見演出與發放內容）。

開場演出範例

Data/Show/StageStart.json

{
  "Name": "模組試煉 深淵_開場",
  "Tag": "劇情",
  "Shows": [
    "<BG>Background_ModAbyss,0,#00000000",
    "<BG>Background_ModAbyss,1,#FFFFFF",
    "<Var>TalkBoxTopDownDontShow,=,0",
    "<Talk>深淵的最底層，傳來了不合時宜的聖歌。",
    "<Image>Mid,Emma,Normal",
    "<Talk>艾瑪：……♪",
    "<Image>Mid,Emma,Shock",
    "<ImageShake>Mid",
    "<Talk>艾瑪：啊，有客人。",
    "<Talk>",
    "<Image>",
    "<BG>,1"
  ]
}
慣例
  • 開頭 <BG>名稱,0,#00000000 + <BG>名稱,1,#FFFFFF = 背景淡入
  • <Talk> 不帶內容 = 關掉對話框
  • <Image> 不帶參數 = 清掉三個槽的立繪
  • 結尾 <BG>,1 把背景淡出，讓戰鬥畫面接手

「打贏才入隊」

比 AutoRun 更自然的角色發放方式 —— AutoRun 是「一啟用就給」， 放在勝利演出則是「玩家打贏才拿到」：

"<Image>Mid,Emma,Laugh",
"<Talk>艾瑪：那麼，照約定，從今天起我就跟著你們了。",
"<Talk>",
"<Image>",
"<AddRole>艾瑪",
"<BG>,1"
重複通關不用自己加旗標 <AddRole> 對已經持有的角色是安全的 —— 直接跳過，不會重複給、也不會把等級打回 1。

戰鬥中的回合演出

戰鬥進行中的每個回合開始時也可以插演出。這種不用填在關卡欄位裡， 命名對上就會被叫到：

{關卡Name}_Wave{波次}_{PlayerTurn|EnemyTurn}{該波第幾回合}

波次與回合都從 1 開始。例如：

演出 Name時機
模組試煉 深淵_Wave2_PlayerTurn1第二波、玩家的第一個回合
模組試煉 深淵_Wave2_PlayerTurn第二波的每個玩家回合
模組試煉 深淵_PlayerTurn3整場的第 3 回合（不分波次）
帶數字的優先於不帶數字的 同時存在 _PlayerTurn1 和 _PlayerTurn 時， 第一回合會播帶數字的那個。

戰鬥中演出的慣例不同

劇情段用背景圖，戰鬥中用 null 加半透明黑當遮罩， 蓋在戰鬥畫面上：

"<BG>null,0,#00000000",
"<BG>null,0.5,#000000CC",      把戰鬥畫面壓暗
"<Wait>1",
"<Image>Mid,Emma,Shock",
"<Talk>艾瑪：等一下，你們是認真的嗎？",
"<Talk>",
"<Image>",
"<BG>,0.5",                    收掉遮罩，回到戰鬥
"<EnemyImage>艾瑪,Emma,Sad"    順手換掉場上那隻的表情
<EnemyImage> 要放在遮罩收掉之後 放在遮罩還蓋著的時候換表情，玩家看不到變化。
<EnemyImage> 的第一段是敵人的資料 Name 第二段起才是「PSB名,表情,服裝」。跟 <Image> 的槽位參數不同。

讓玩家真的看得到關卡

寫進資料表只代表「關卡存在」，玩家還沒有它 要靠 AutoRun 演出發給玩家，兩行都不能省： 
Data/Show/AutoRun.json

{
  "Name": "MyMod",
  "Tag": "AutoRun",
  "Shows": [
    "<AddStageGroup>模組",
    "<AddStage>模組試煉 深淵"
  ]
}

詳見演出與發放內容。

技能

技能放 Data/Skill/。角色的技能欄位有一個容易寫錯的對應規則：

Skill 的前 4 個是「基礎技能」，第 5 個起才吃條件 Skill 前 4 個一開始就會，不需要條件。
第 5 個之後依序對應 ElseSkillCon： 
Skill[4] <- ElseSkillCon[0]
Skill[5] <- ElseSkillCon[1]
...
所以 ElseSkillCon 不需要為前 4 個技能補空字串。
