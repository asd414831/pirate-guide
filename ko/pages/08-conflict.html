여러 모드

플레이어는 한 번에 여러 모드를 활성화할 수 있습니다. 이 장은 누가 이기는지에 관한 것입니다.

적용 순서

게임 시작 시:

  1. 게임 자체 데이터가 로드됩니다
  2. 모드는 목록 순서대로 하나씩 겹쳐서 적용됩니다
늦은 승리목록 아래쪽의 모드는 앞서 있는 모드를 덮어씁니다. 데이터 테이블, 이미지 및 오디오에도 동일한 규칙이 적용됩니다.

충돌이 발생하는 경우

친절한갈등이 발생할 때결과
데이터두 개의 모드 편집같은 분야의 같은Name나중의 값이 승리한다
이미지두 개의 모드가 제공됩니다같은 경로와 파일 이름나중 이미지가 승리
오디오두 개의 모드가 제공됩니다같은 파일 이름나중 파일이 우선한다
다른 필드를 편집하는 것은 충돌이 아닙니다모드 A는 아이템의 {}를 변경합니다SellPrice, 모드 B가 그것을 변경합니다Desc— 둘 다 적용됩니다. 병합은 실제로 작성된 필드만 덮어쓰므로요.
이것이 모드가 예상보다 더 호환성이 좋은 주된 이유입니다.

플레이어는 순서를 변경할 수 있습니다

모드 매니저는 수동 정렬을 지원합니다. 모드가 충돌할 때 플레이어는 선호하는 모드를 더 아래로 이동할 수 있습니다.

그래서 '호환되지 않음'은 보통 그렇지 않다두 개의 모드가 충돌할 때, 먼저 플레이어에게 순서를 바꿔 보라고 요청하세요. 진정으로 해결 불가능한 경우는 "두 모드가 동일한 필드를 서로 다른 값을 저장하는 데 필요할 때"입니다.

모드 제작자를 위한 권장 사항

1. 가능한 한 적은 필드만 변경하세요

실제로 변경하고 싶은 것만 작성하세요아이템의 가격을 올리려면, 오직 작성하십시오Name그리고SellPrice.
전체 항목을 '완전함을 위해' 복사하지 마세요 — 이는 동일한 항목을 건드리는 다른 모든 모드와 충돌하며, 게임 업데이트 후에는 오래된 값이 새 값을 덮어쓰게 됩니다.

2. 새로운 콘텐츠에는 독특한 이름을 사용하세요

아이템 / 캐릭터 / 스킬을 추가할 때, 접두사를 붙이세요Name자신의 무언가와 함께:

"Name": "MyMod_SuperPotion"

그것은 다른 사람의 추가 내용과 게임 자체가 나중에 추가할 수 있는 내용과 충돌하는 것을 피합니다.

접두사는 내부용이며; 플레이어는 절대 볼 수 없습니다플레이어가 본다Name_I2, 그래서Name원하는 만큼 못생길 수 있다.

3. 이미지와 오디오에도 접두사를 붙이세요

Images/RoleHead/MyMod_NewHero.png
Music/BGM_MyMod_Theme.ogg

당신이 하지 않는 한고의로게임이나 다른 모드의 에셋을 교체하고 싶다면, 접두사를 붙이세요.

4. 설명에서 변경한 내용을 말하세요

{
  "description": "Changes:\n- All enemy HP x2\n- Herb sells for 500\n\nConflicts with other enemy-stat mods."
}

그래서 플레이어들이 무언가 문제가 생겼을 때 어떤 모드를 꺼야 하는지 알 수 있습니다.

모드는 다른 모드에 의존할 수 없습니다

의존성 메커니즘이 없습니다당신은 "requires mod XX"를 선언할 수 없습니다. 게임은 이를 확인하지 않으며 경고하지도 않습니다.
만약 당신의 모드가 실제로 다른 모드에 의존한다면(예를 들어, 그것이 추가하는 아이템을 참조하는 경우), 그렇게 명시하세요description그리고 '설치되지 않음' 경우를 직접 처리하십시오.

문제가 있는 모드는 다른 모드와 분리됩니다

오류가 격리되었습니다형식이 잘못된 JSON 파일은 해당 파일만 건너뜁니다. 같은 모드의 다른 파일들과 다른 모드들은 계속 작동합니다.
그래서 10개의 모드를 가진 플레이어가 하나가 고장난 상태라도 여전히 플레이할 수 있습니다 — 그 콘텐츠 부분은 단순히 적용되지 않습니다.
