연출과 콘텐츠 지급

데이터를 기록하는 것만으로는 그 물건이 존재한다는 뜻입니다. 플레이어는 여전히 그것을 가지고 있지 않습니다. 이 장에서는 실제로 그것을 전달하는 것에 대해 다룹니다.

사람들이 놓치는 단계입니다문자 아래에 추가합니다Data/Role/, 데이터는 완벽하고 — 플레이어는 결코 그것들을 얻지 못할 것이다.
아이템에는 가격 필드가 있어서 아이템이 혼자서 상점에 나타날 수 있습니다.캐릭터와 스테이지는 그렇지 않다.그들에게 허용하는 유일한 방법은 show 명령어입니다.

연출이란?

연출는 게임 명령어의 목록입니다. 그것은 이야기 대화일 수도 있고 순수한 데이터 조작일 수도 있습니다. 연출는 다음에 존재합니다Data/Show/, 파일당 하나씩.

{
  "Name": "MyMod",
  "Tag": "AutoRun",
  "Shows": [
    "<AddRole>NewHero"
  ]
}
연출에는 정확히 네 개의 필드가 있습니다ID/Name/Tag/Shows설명 필드가 없습니다; 하나를 추가해도 아무 효과가 없습니다.

자동 실행: 모드가 스스로 작동할 수 있는 유일한 훅

세트Tag에게AutoRun그리고 연출가 자동으로 재생됩니다새 게임 시작 후 그리고 게임 불러오기 후.

Data/Show/AutoRun.json

{
  "Name": "MyMod",
  "Tag": "AutoRun",
  "Shows": [
    "<AddRole>NewHero",
    "<AddItem>SuperPotion,1"
  ]
}
AutoRun은 한 번이 아니라 매번 실행됩니다새 게임 시작과 게임 불러오기 시마다 작동합니다.
그건 보통 무해합니다 —<AddRole>그리고<AddItem>플레이어가 이미 가지고 있는 항목은 건너뛰세요. 중복되지 않으며, 레벨도 초기화되지 않습니다.

정말로 한 번만 필요하다면, 플래그로 그것을 보호하세요:

{
  "Name": "MyMod",
  "Tag": "AutoRun",
  "Shows": [
    "<if>{MyModInitialised}==0",
    "<AddRole>NewHero",
    "<Var>MyModInitialised,=,1",
    "<endif>"
  ]
}
모드의 이름을 사용하세요NameName병합 키입니다; 두 개의 모드가 동일한 이름의 AutoRun 연출를 가지고 있으면 나중 것이 이전 것을 조용히 덮어씁니다. 모드 이름을 사용하면 충돌을 피할 수 있습니다.
Tag같음이 아니라 '포함' 확인입니다"Tag": "AutoRun,Story"여전히 AutoRun으로 간주됩니다. 대소문자 구분도 없습니다, 그래서autorun작동합니다.

캐릭터 부여

<AddRole>NewHero

주장은 그 캐릭터의 것이다Name데이터 테이블에서 (아님Name_I2).

승무원 갤러리를 위한 두 가지 추가 조건
  • ID0보다 큰
  • Name비어 있지 않음
두 가지 모두 없으면, 캐릭터는 이후에도 보이지 않은 상태로 남습니다<AddRole>달린다.

스테이지 지급

두 줄 모두 필요합니다.

<AddStageGroup>Mods
<AddStage>Abyss Trial
없이<AddStageGroup>무대가 보이지 않는다스테이지는 그룹에 속해야 합니다. 그룹이 없으면 스테이지 메뉴에 들어갈 자리가 없습니다.
게임에는 '그룹'이라는 내장 기능이 포함되어 있습니다Mods직접 사용할 수 있습니다.
반복해서 실행하는 것은 안전합니다플레이어가 이미 가진 그룹과 단계는 두 번 추가되지 않습니다.

아이템 부여

<AddItem>SuperPotion,1
항목은 보통 자동 실행이 필요하지 않습니다세트SellPrice그리고 아이템이 플레이어가 구매할 수 있도록 상점에 나타납니다.<AddItem>직접 건네주는 용도일 뿐입니다.

자동 실행에 대한 한 가지 경고

저장이 이야기 중간이라면, AutoRun이 그것과 함께 실행됩니다컷신을 재개하는 저장파일을 불러오면 오토런이 화면을 차지하기 위해 경쟁하게 됩니다.
AutoRun을 순수 데이터 명령으로 유지—<AddRole>,<AddItem>,<AddStage>,<Var>.
대화와 속도 조절을 위해, a스테이지 승리 연출더 나은 집입니다 (다음 장을 참조하십시오).
여러 모드의 자동 실행이 차례대로 실행됩니다절대 동시에 하지 마세요. 순서는 모드 리스트 순서대로(위에서 아래로)입니다.
그래서 a<Wait>귀하의 AutoRun은 의도한 대로 작동하며 — 다른 모드가 방해하지 않습니다.

이름 규칙: 게임의 연출 슬롯 연결하기

게임의 다양한 부분이 연출를 찾습니다고정된 이름. 당신의 연출 이름을 맞춰서 지으세요 그리고 그것은 — 아니라고 불립니다Tag필요했다.

홈 화면 캐릭터 대화

플레이어가 홈 화면에서 캐릭터 초상화를 클릭할 때 재생:

RoomTalk_<character Name>

캐릭터를 위한Name이다NewHero:

Data/Show/RoomTalk.json

{
  "Name": "RoomTalk_NewHero",
  "Shows": [
    "<Var>RoomTalkCount,+,1",
    "<if>{RoomTalkCount}>3",
    "<Var>RoomTalkCount,=,1",
    "<endif>",
    "<if>{RoomTalkCount}==1",
    "<MateImage>NewHero",
    "<MateTalk>{CurrentHomeCharacterName}: Hey there.",
    "<elseif>{RoomTalkCount}==2",
    "<MateTalk>{CurrentHomeCharacterName}: You again.",
    "<elseif>",
    "<MateTalk>{CurrentHomeCharacterName}: Stop poking me.",
    "<endif>"
  ]
}
이것을 건너뛰는 것은 오류가 아닙니다캐릭터는 홈 화면에서 조용히 서 있기만 합니다. 반응을 원하면 추가하세요.
데이터 테이블의 것을 사용한다는 점에 유의하세요Name, 번역된 표시 이름이 아니라.

명령 참조

명령효과
<AddRole>Name플레이어에게 캐릭터를 주세요
<AddItem>Name,count아이템을 주세요
<AddStageGroup>name스테이지 그룹 잠금 해제
<AddStage>Name스테이지 잠금 해제
<Var>name,=,value변수를 설정하다 (=/+/-)
<if>cond…<endif>조건부의, ~와 함께<elseif>사이
<Talk>text대화. 텍스트가 없으면 대화 상자를 닫습니다
<MateTalk>text홈 화면 대화
<Wait>seconds일시 정지
<BG>name,seconds,colour배경.<BG>,1서서히 사라지다
<Image>slot,character,face,body초상화. 인수가 없으면 모두 지웁니다
<MateImage>character,face,body홈 화면 세로 모드 (슬롯 인수 없음)
<BGM>name음악을 바꾸다
<Sfx>name효과음을 재생하다
전체 명령 목록은 연출 편집기에서 확인할 수 있습니다복잡한 인수가 있는 명령어가 많이 있습니다. 작성은 ~에서 보여줍니다연출 편집기메뉴를 외우는 대신 설명과 함께 메뉴에서 선택할 수 있게 해줍니다.

대화 규약

화자를 '이름: 내용'으로 작성하세요:

<Talk>NewHero: Good morning.
캐릭터와 일치하는 이름이 자동으로 색이 칠해지고 스포트라이트가 켜집니다데이터 테이블과 대조됨Name. 일치하지 않는다는 것은 단순한 일반 텍스트를 의미하며 — 오류가 아님.
