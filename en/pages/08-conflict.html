Multiple Mods

Players can enable many mods at once. This chapter is about who wins.

Apply order

At game start:

  1. The game's own data loads
  2. Mods are layered on one at a time, in list order
Later wins Mods further down the list override earlier ones. Same rule for data tables, images and audio.

What counts as a conflict

KindConflicts whenResult
Datatwo mods edit the same field of the same Namelater value wins
Imagestwo mods ship the same path and filenamelater image wins
Audiotwo mods ship the same filenamelater file wins
Editing different fields isn't a conflict Mod A changes an item's SellPrice, mod B changes its Desc — both apply, because merging only overwrites fields that were actually written.
This is the main reason mods are more compatible than you'd expect.

Players can reorder

The Mod Manager supports manual ordering. When mods clash, players can move the one they prefer further down.

So "incompatible" usually isn't When two mods fight, ask players to try reordering first. The genuinely unsolvable case is "both mods need the same field to hold a different value".

Advice for authors

1. Change as few fields as possible

Only write what you actually want to change To make an item cost more, write only Name and SellPrice.
Don't copy the whole entry "for completeness" — that conflicts with every other mod touching the same entry, and after a game update your stale values would override the new ones.

2. Use distinctive names for new content

When adding items / characters / skills, prefix Name with something of your own:

"Name": "MyMod_SuperPotion"

That avoids colliding with other people's additions, and with content the game itself may add later.

The prefix is internal; players never see it Players see Name_I2, so Name can be as ugly as you like.

3. Prefix images and audio too

Images/RoleHead/MyMod_NewHero.png
Music/BGM_MyMod_Theme.ogg

Unless you deliberately want to replace the game's or another mod's assets, prefix them.

4. Say what you changed in the description

{
  "description": "Changes:\n- All enemy HP x2\n- Herb sells for 500\n\nConflicts with other enemy-stat mods."
}

So players know which mod to turn off when something breaks.

Mods can't depend on each other

There is no dependency mechanism You can't declare "requires mod XX". The game doesn't check and won't warn.
If your mod genuinely depends on another (referencing an item it adds, say), say so in description and handle the "not installed" case yourself.

One broken mod doesn't take down the rest

Errors are isolated A malformed JSON file only skips that file. Other files in the same mod, and other mods, keep working.
So a player with ten mods, one of them broken, can still play — that part of the content simply doesn't apply.
