Stages & Enemies

Building a complete battle. Enemies, AI, waves, backgrounds, cutscenes.

Enemies

Data/Enemy/Emma.json

{
  "Name": "Emma",
  "ID": 9201,
  "PSB": "Emma,Normal,Normal",
  "WellTerrain": "Cave",
  "StartHP": 420, "LvAddHP": 18,
  "StartAtk": 48, "LvAddAtk": 1,
  "Pos_y": -1120, "Sca": 48,
  "DoID":    ["1",          "1",           "1"],
  "DoCON":   ["",           "{Turn}%4==3", "{Turn}%3==0"],
  "DoSkill": ["Combo Punch", "Rapid Heal", "Defend"]
}

Enemy AI: three parallel lists

DoID / DoCON / DoSkill are three aligned lists. The same index across all three is one rule.

FieldMeaning
DoIDWeight. Higher is picked more often. -1 means an opening passive (that slot's DoSkill must be a passive skill)
DoCONTrigger condition. Empty string means always true
DoSkillSkill name. Must match one the game has, or one you added under Data/Skill/
Mismatched lengths are truncated to the shortest The extras are silently ignored, with no error. Count them yourself.

The example above reads as:

  • Normally uses "Combo Punch"
  • Turns 3, 7, 11… use "Rapid Heal" ({Turn}%4==3)
  • Turns 3, 6, 9… use "Defend" ({Turn}%3==0)

Portrait position and scale

FieldNotes
Pos_yVertical position in the battle screen. Regular enemies sit around -1120
ScaScale. Regular enemies are around 70–80
Fastest approach: copy an existing enemy of similar build Find one about the right size in game, copy its Pos_y / Sca, then fine-tune.
Adjusting portraits doesn't need a game restart Save the file, return to the title screen, Start New Game or Load Game, and it applies.

Where enemy portraits go

Exactly the same rules as characters (see Adding Images); the only difference is the field is called PSB.

PSB's three parts are "PSB name, face, body":

"PSB": "Emma,Normal,Normal"
Characters and enemies can share one portrait set The example Emma appears as an enemy first, then joins the party using the same PSB after you beat her.
Each table has its own Pos_y / Sca — the battle screen and the home screen frame her differently.

Stages

Data/Stage/AbyssTrial.json

{
  "Name": "Abyss Trial",
  "ID": 9201,
  "Group": "Mods",
  "Tag": "Battle",
  "Rank": 1,
  "FightWinExp": "60", "FightWinMoney": "60",
  "FightWhere": "Cave",
  "FightBackground": "Background_ModAbyss, Background_ModAbyss_Night",
  "FightBGM": "BGM_Fight2",
  "EnemyLv": ["3", "5"],
  "Enemys":  ["Emma", "Emma, Jellyfish"],
  "GetItem": ["Apple"],
  "GetItemProbability": ["0.5"]
}
FieldNotes
GroupGroup in the stage menu. The game ships a built-in Mods group
TagWithout "Battle" it only plays a show and never starts a fight
FightWhereLocation; affects terrain matchups
FightBackgroundBattle background. Comma-separated for one per wave
FightBGMBattle music. Comma-separated for one per wave

Waves

One element of Enemys is one wave Several enemies in the same wave go in one string, comma-separated. 
"Enemys": ["Emma", "Emma, Jellyfish"]     wave 1: one enemy, wave 2: two
"Enemys": ["Emma,Jellyfish"]              one wave of two (spaces optional)
You can use the game's existing enemies "Jellyfish" above is a base-game enemy — you don't have to add your own.
Never put two identically-named enemies in one wave Don't write "Emma, Emma".
Several parts of the game look enemies up by name to find their position on the field. With two of the same name only the first is ever found — the second one's effect coordinates and targeting land on the first.
To field two of the same kind, duplicate the data under a different name (the game's own "Knight / Knight B / Knight C" does exactly this).
The same name across different waves is fine (each wave is cleared and respawned).

Parallel lists

Field pairAlignment
Enemys / EnemyLvone element = one wave
FightBackground / FightBGMcomma-separated, one per wave
GetItem / GetItemProbabilitysame index = same drop
Short lists are reused If EnemyLv runs out the game computes levels automatically; FightBackground / FightBGM fall back to the first entry.

Stage cutscenes

Three fields take show names:

FieldWhen
StartShowOn entering, before the fight
FightWinShowAfter winning
FightLoseShowAfter losing

All three are optional. The shows themselves live in Data/Show/ (see Shows & Granting Content).

Example opening show

Data/Show/StageStart.json

{
  "Name": "Abyss Trial_Start",
  "Tag": "Story",
  "Shows": [
    "<BG>Background_ModAbyss,0,#00000000",
    "<BG>Background_ModAbyss,1,#FFFFFF",
    "<Talk>From the depths of the abyss came an ill-timed hymn.",
    "<Image>Mid,Emma,Normal",
    "<Talk>Emma: ……♪",
    "<Image>Mid,Emma,Shock",
    "<ImageShake>Mid",
    "<Talk>Emma: Oh. Visitors.",
    "<Talk>",
    "<Image>",
    "<BG>,1"
  ]
}
Conventions
  • Opening <BG>name,0,#00000000 + <BG>name,1,#FFFFFF fades the background in
  • <Talk> with no text closes the dialogue box
  • <Image> with no arguments clears all three portrait slots
  • Closing <BG>,1 fades out so the battle screen can take over

"Join the party only if you win"

A more natural way to grant a character than AutoRun — AutoRun gives them the moment the mod is enabled; a victory show makes the player earn it:

<Image>Mid,Emma,Laugh
<Talk>Emma: Well then. As agreed, I'm with you from today.
<Talk>
<Image>
<AddRole>Emma
<BG>,1
No flag needed for repeat clears <AddRole> is safe on a character the player already has — it's skipped, without duplicating or resetting their level.

Mid-battle turn shows

Shows can also fire at the start of any turn during a fight. These aren't referenced from the stage data — matching the name is enough:

{StageName}_Wave{n}_{PlayerTurn|EnemyTurn}{turn}

Waves and turns both count from 1. For example:

Show nameWhen
Abyss Trial_Wave2_PlayerTurn1Wave 2, the player's first turn
Abyss Trial_Wave2_PlayerTurnEvery player turn in wave 2
Abyss Trial_PlayerTurn3Turn 3 of the whole battle (any wave)
Numbered beats unnumbered With both _PlayerTurn1 and _PlayerTurn present, turn 1 plays the numbered one.

Mid-battle conventions differ

Story sections use a background image; mid-battle uses null plus a semi-transparent black overlay on top of the battle screen:

<BG>null,0,#00000000
<BG>null,0.5,#000000CC      dim the battle screen
<Wait>1
<Image>Mid,Emma,Shock
<Talk>Emma: Wait — you're serious?
<Talk>
<Image>
<BG>,0.5                    drop the overlay, back to the fight
<EnemyImage>Emma,Emma,Sad   change her expression on the field
<EnemyImage> must come after the overlay clears Change the expression while the screen is still dimmed and the player won't see it.

Making the stage visible to players

Data alone only means the stage exists — the player doesn't have it Grant it with an AutoRun show. Both lines are required: 
Data/Show/AutoRun.json

{
  "Name": "MyMod",
  "Tag": "AutoRun",
  "Shows": [
    "<AddStageGroup>Mods",
    "<AddStage>Abyss Trial"
  ]
}

See Shows & Granting Content.

Skills

Skills go in Data/Skill/. The character skill fields have one mapping rule that's easy to get wrong:

The first 4 Skill entries are base skills; conditions start at the 5th The first four are available from the start and need no condition.
From the fifth onwards they map in order to ElseSkillCon: 
Skill[4] <- ElseSkillCon[0]
Skill[5] <- ElseSkillCon[1]
…
So ElseSkillCon does not need empty placeholders for the first four.

Official example mods

The game ships a complete example Under Mods/ there's an official example covering a whole stage: custom enemy with expression variants, a two-wave stage that changes background per wave, opening / victory / defeat cutscenes, and a character who joins when you win.
When unsure how a field should be written, go look at it.
