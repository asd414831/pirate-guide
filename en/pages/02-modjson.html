mod.json Fields

The mod's ID card. It decides what players see in the mod list.

Where it goes

Mods/<your mod folder>/mod.json
No mod.json means it isn't a mod When scanning Mods/, the game only treats subfolders containing a mod.json as mods. Without it your folder is ignored entirely — it won't appear in the list, and there's no error message either.

Full example

{
  "name": "Harder Pirates",
  "author": "Some Player",
  "version": "1.2.0",
  "description": "Enemies hit harder, drops are rarer.\nMeant for new game plus.",
  "icon": "icon.png"
}

Field reference

FieldTypeIf omittedNotes
nametextfolder name is used Display name in the mod list. Any language.
authortextshows "Unknown author" Your name or handle.
versiontextshows "-" Display only. The game never compares versions — 1.0 or v2-beta are equally fine.
descriptiontextempty Description. Use \n for line breaks.
icontexticon.png Relative path to the thumbnail. Falls back to a default image if the file is missing.
Every field is optional Even an empty {} works — the game falls back to the folder name. Omitting a field never breaks the mod. That's deliberate.

Thumbnail

By default the game looks for icon.png in the mod folder. To use a different name or a subfolder:

{
  "icon": "art/my-thumbnail.png"
}

The path is relative to your mod folder, not to Mods/.

Line breaks

JSON strings can't contain a literal newline — use \n:

{
  "description": "First line\nSecond line\n\nThird line after a blank one"
}
Escape backslashes in Windows paths \ is a special character in JSON. Use forward slashes for the icon path — art/icon.png, not art\icon.png. A literal backslash needs to be doubled (\\), which is easy to get wrong.

What happens if it's malformed

If mod.json exists but has a syntax error (missing comma, extra comma, unclosed quote), the mod still appears in the list but is flagged as broken.

That's deliberate If broken mods simply vanished, players would assume the files were in the wrong place with no way to investigate. Listing it and flagging it tells them "it's there, but something's wrong".

Common JSON mistakes:

{
  "name": "My Mod",
  "author": "Someone",     <-- trailing comma on the last field
}

{
  "name": "My Mod"
  "author": "Someone"      <-- missing comma between fields
}

{
  'name': 'My Mod'         <-- JSON requires double quotes
}
Editing in VS Code avoids nine tenths of these It highlights syntax errors as you type. Alternatively, paste the file into any online JSON validator.

Don't rename the folder

The enabled state is tied to the folder name, not the name field Changing name in mod.json: safe, only the display name changes.
Changing the folder name: as far as the game is concerned it's a different mod — enabled state resets and players have to turn it back on. Don't rename after release.
