Shows & Granting Content

Writing data only means the thing exists. The player still doesn't have it. This chapter is about actually handing it over.

This is the step people miss You add a character under Data/Role/, the data is perfect — and the player will never get them.
Items have a price field so they can appear in the shop on their own. Characters and stages don't. The only way to grant them is a show command.

What a show is

A show is a list of game commands. It can be story dialogue, or pure data manipulation. Shows live in Data/Show/, one per file.

{
  "Name": "MyMod",
  "Tag": "AutoRun",
  "Shows": [
    "<AddRole>NewHero"
  ]
}
A show has exactly four fields ID / Name / Tag / Shows. There's no description field; adding one does nothing.

AutoRun: a mod's only hook to act on its own

Set Tag to AutoRun and the show plays automatically after Start New Game and after Load Game.

Data/Show/AutoRun.json

{
  "Name": "MyMod",
  "Tag": "AutoRun",
  "Shows": [
    "<AddRole>NewHero",
    "<AddItem>SuperPotion,1"
  ]
}
AutoRun runs every time, not once It fires on every Start New Game and every Load Game.
That's usually harmless — <AddRole> and <AddItem> skip anything the player already has. They won't duplicate, and they won't reset levels.

If you genuinely need it once only, guard it with a flag:

{
  "Name": "MyMod",
  "Tag": "AutoRun",
  "Shows": [
    "<if>{MyModInitialised}==0",
    "<AddRole>NewHero",
    "<Var>MyModInitialised,=,1",
    "<endif>"
  ]
}
Use your mod's name for Name Name is the merge key; if two mods have AutoRun shows with the same name, the later one silently overwrites the earlier. Using your mod name avoids collisions.
Tag is a "contains" check, not equality "Tag": "AutoRun,Story" still counts as AutoRun. Case-insensitive too, so autorun works.

Granting a character

<AddRole>NewHero

The argument is the character's Name from the data table (not Name_I2).

Two more conditions for the crew gallery
  • ID greater than 0
  • Name not empty
Without both, the character stays invisible even after <AddRole> runs.

Granting a stage

Both lines are required.

<AddStageGroup>Mods
<AddStage>Abyss Trial
Without <AddStageGroup> the stage is invisible Stages have to hang off a group. No group, no place for it in the stage menu.
The game ships a built-in group called Mods you can use directly.
Running it repeatedly is safe Groups and stages the player already has aren't added twice.

Granting items

<AddItem>SuperPotion,1
Items usually don't need AutoRun Set SellPrice and the item shows up in the shop for players to buy. <AddItem> is only for handing it over directly.

One caveat about AutoRun

If the save is mid-story, AutoRun runs alongside it Loading a save that resumes a cutscene means AutoRun competes with it for the screen.
Keep AutoRun to pure data commands — <AddRole>, <AddItem>, <AddStage>, <Var>.
For dialogue and pacing, a stage victory show is a better home (see the next chapter).
Multiple mods' AutoRun shows run one after another Never concurrently. The order is the mod list order (top to bottom).
So a <Wait> in your AutoRun does what you intended — no other mod interrupts.

Naming conventions: filling the game's show slots

Various parts of the game look for shows by a fixed name. Name your show to match and it gets called — no Tag needed.

Home screen character dialogue

Plays when the player clicks a character portrait on the home screen:

RoomTalk_<character Name>

For a character whose Name is NewHero:

Data/Show/RoomTalk.json

{
  "Name": "RoomTalk_NewHero",
  "Shows": [
    "<Var>RoomTalkCount,+,1",
    "<if>{RoomTalkCount}>3",
    "<Var>RoomTalkCount,=,1",
    "<endif>",
    "<if>{RoomTalkCount}==1",
    "<MateImage>NewHero",
    "<MateTalk>{CurrentHomeCharacterName}: Hey there.",
    "<elseif>{RoomTalkCount}==2",
    "<MateTalk>{CurrentHomeCharacterName}: You again.",
    "<elseif>",
    "<MateTalk>{CurrentHomeCharacterName}: Stop poking me.",
    "<endif>"
  ]
}
Skipping this isn't an error The character just stands there silently on the home screen. Add it if you want reactions.
Note it uses the data table's Name, not the translated display name.

Command reference

CommandEffect
<AddRole>NameGive the player a character
<AddItem>Name,countGive items
<AddStageGroup>nameUnlock a stage group
<AddStage>NameUnlock a stage
<Var>name,=,valueSet a variable (= / + / -)
<if>cond … <endif>Conditional, with <elseif> in between
<Talk>textDialogue. With no text, closes the dialogue box
<MateTalk>textHome screen dialogue
<Wait>secondsPause
<BG>name,seconds,colourBackground. <BG>,1 fades out
<Image>slot,character,face,bodyPortrait. With no arguments, clears all
<MateImage>character,face,bodyHome screen portrait (no slot argument)
<BGM>nameChange music
<Sfx>namePlay a sound effect
The full command list is in the Show Editor There are many commands with fiddly arguments. Writing shows in the Show Editor lets you pick from a menu with descriptions instead of memorising them.

Dialogue conventions

Write the speaker as "Name: text":

<Talk>NewHero: Good morning.
A name matching a character gets coloured and spotlit automatically Matched against the data table's Name. No match just means plain text — not an error.

Opening and closing a story section

Follow the game's own convention:

<BG>MyBG,0,#00000000      set the background, fully transparent
<BG>MyBG,1,#FFFFFF        fade in over 1 second
<Talk>Someone: Opening line.
<Talk>                     close the dialogue box
<Image>                    clear the portraits
<BG>,1                     fade the background out

Checklist

Character or stage added but the player can't see it:

  1. Did you write an AutoRun show? (most common cause)
  2. Does Tag contain AutoRun?
  3. Is the <AddRole> argument the data table's Name? (not Name_I2)
  4. Is ID greater than 0?
  5. For stages, did you include <AddStageGroup>?
  6. Did you return to the title screen and Start New Game or Load Game?
