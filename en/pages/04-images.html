Adding Images

Mods can ship their own artwork. Drop it in Images/ and it loads.

The basic rule

Mods/<your mod>/Images/<mirror the game's structure>/<name>.png
Just mirror the game's own folder structure There are no special rules to memorise. The game keeps character portraits in RoleHead/, so your mod puts them in Images/RoleHead/. That's it.

Example

MyMod/
├── mod.json
├── Data/
│   └── Role/
│       └── NewHero.json
└── Images/
    ├── RoleHead/
    │   └── NewHero.png      face icon
    └── Role/
        └── NewHero.png      full portrait

Folder map

FolderContentsData field
Images/Role/Full portraits (characters and enemies)PSB
Images/RoleHead/Face iconsImageName / EyeImageName
Images/Icon/Item and buff iconsIconName
Images/Background/BackgroundsFightBackground, script <BG>
Images/Sticker/Sticker graphicsscript <Sticker>
IconName includes the subpath An icon at Images/Icon/Buff/MyIcon.png is referenced as "Icon/Buff/MyIcon".
The other fields (PSB, ImageName) take just the filename.

Then point the data at it:

{
  "Name": "NewHero",
  "Name_I2": "New Hero",
  "ImageName": "NewHero"
}
No folder, no .png The file is at Images/RoleHead/NewHero.png; the data says "NewHero". The game knows which folder to look in.

Expression and outfit variants

Portraits come in two layouts, depending on whether you want variants.

(A) No variants — a single image

Images/Role/Nausea.png

(B) With variants — a folder instead

Images/Role/Nausea/Body/Body_Normal.png
Images/Role/Nausea/Body/Body_Dark.png
Images/Role/Nausea/Face/Face_Normal.png
Images/Role/Nausea/Face/Face_Laugh.png
This is the most common mistake People assume the expression image only needs to be face-sized. It doesn't — it must be a full-body canvas with everything but the face transparent.
Crop it small and it lands in the top-left corner instead.
RuleDetail
Folder name = group nameCurrently Body (body / outfit) and Face (expression)
Filename = layer nameYou add the Body_ / Face_ prefix yourself
Every image is full-sizeFull canvas, transparent background, all the same dimensions
Stacking orderComposited at identical coordinates, Face on top of Body

Mixing outfits and expressions

Which variant shows by default

SituationResult
the group has <Group>_Normalthat one is shown
the group has no Normalthe whole group is hidden by default

So if you only ship Face_Laugh.png, there's normally no expression at all until a script asks for it.

Always include Face_Normal.png In the crew gallery players can flip through every expression variant, and <Group>_Normal is always the first page — that's what they see when they open the portrait.
If you have no extra expressions, make Face_Normal.png fully transparent (the Body image already has a face).
Gallery page order Alphabetical by filename, except Normal which is always first.
For a deliberate "no expression" page, follow the game's convention and add Face_Null.png (fully transparent) — names containing Null are pinned to the last page.

Switching variants from a script

The first argument of <Image> is the slot, not the character Slots are Mid / Left / Right. The character name starts at the second argument. 
<Image>Mid,Nausea,Laugh        face becomes Face_Laugh
<Image>Mid,Nausea,,Dark        body becomes Body_Dark
<Image>Mid,Nausea,Laugh,Dark   both at once
<Image>Mid,Nausea,-            hide that group entirely
<Image>Mid                     clear that slot
<Image>                        clear all three slots

Expressions and outfits omit the prefix — write Laugh, not Face_Laugh.

Two related commands take no slot argument and start at the character name:

<MateImage>Nausea,Laugh        home screen portrait
<EnemyImage>Emma,Emma,Shock    swap an enemy portrait mid-battle
<EnemyImage>'s first argument is the enemy's data Name "PSB name, expression, outfit" starts from the second argument.
When a variant isn't found The game logs it (e.g. group [Face] has no [Face_Angry]) and that group is hidden.

Format

ItemRequirement
File formatPNG
TransparencySupported (usually required for portraits and icons)
DimensionsNo hard limit, but match the game's own art of the same kind or it'll render too large or too small

Replacing the game's art

Use the same path and filename as the original and yours wins.

Images/RoleHead/Rackham.png      <-- replaces Rackham's face icon
Mod images take priority over the game's That's deliberate — "replace the portraits" and "reskin the UI" should be possible mods. No extra configuration; the same name is enough.
The filename must match exactly One character off and it isn't a replacement — it's a new image nobody uses.

Subfolders matter here

Unlike audio, the image folder structure is part of the lookup:

Images/RoleHead/Nausea.png    <-- face icon
Images/Role/Nausea.png        <-- full portrait

Two different images. Put one in the wrong folder and it's simply not found.

Audio works the opposite way Audio subfolders are purely for your own organisation and don't affect lookup. Image subfolders are part of the path.

Memory

All images load at startup and stay resident A handful to a few dozen is fine. If your mod has hundreds of high-resolution images, players will notice the memory use — that's your call as the author.

Checklist

When an image doesn't show, in order:

  1. Is it a real .png? (not a renamed JPG)
  2. Is it under Images/? (with the s)
  3. Is the subfolder spelled right? (RoleHead, not Rolehead)
  4. Does ImageName match the filename? (without .png)
  5. Using variant folders — did you add the Body_ / Face_ prefix?
  6. Are all variant images the same full-body size?
  7. Did you return to the title screen and Start New Game or Load Game?
