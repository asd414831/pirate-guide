Editing Game Data

The main thing mods do. Change existing values, or add brand new content.

The basic rule

Mods/<your mod>/Data/<table>/<any filename>.json
  • The folder name picks the table — Data/Item/ edits items, Data/Role/ edits characters
  • One JSON file is one entry — one item per file; don't pack several into one file
  • The filename doesn't matter — the game reads the Name field inside. The filename is purely for your own benefit
Both Item and TheItem work The internal table name is TheItem; when the folder is called Item the game prepends The automatically. Both spellings are accepted — one less thing to get wrong.

Merge rules (the important part)

The game already has a full data set. Your JSON is layered on top, not replacing it. The key used for matching is the Name field:

Your NameResult
the game already has that name Edited in place. Only the fields you wrote change; everything else keeps its original value
the game doesn't have it Added as a new entry at the end of the list
Only write the fields you want to change To make an item sell for more, the entire file is two lines:
{ "Name": "Herb", "SellPrice": 500 }
Everything else (name, icon, effect) is untouched.
There is no delete Mods cannot remove existing game content. To make something not appear, set UnlockCon to a condition that never becomes true — don't try to delete it.

Name is the identity

A typo in Name turns an edit into an addition If you meant to edit "Herb" but wrote "Herbb", the game doesn't complain — it assumes you want to add a new item called "Herbb". Result: the original Herb is unchanged and there's a strange new item.
When a mod does nothing, check Name for typos first (including stray spaces and full-width characters).

Finding field names

Field names must match the game's internals exactly, including case. The most reliable way to look them up is the data table view in the Show Editor (see Show Editor), which lists every field of every table.

Or just make a typo on purpose When a field name doesn't exist, the game prints a suggestion:
TheItem has no field "IconImage", skipped. Did you mean "IconName"?
Faster than looking it up.

Adding content needs an ID

New entries must have ID greater than 0, or they're skipped Entries with ID 0 or negative are treated as spreadsheet placeholder rows and never appear in game.
Use 9000 or above to stay clear of content the game itself might add later.
When editing an existing entry you don't need ID at all — the original is kept.

Types: when to use quotes

JSON writes numbers and text differently, and it has to match the game's field type.

{
  "Name": "SuperPotion",
  "SellPrice": 500,          number, no quotes
  "AddHP": 999,              number, no quotes
  "Name_I2": "Super Potion", text, quotes
  "Atk": "20"                text, quotes (see below)
}
Equipment stat fields are text, not numbers Atk / MaxHP / AtkPercent and friends hold formula strings, so write "Atk": "20", not "Atk": 20.
This is what lets stats scale with level. When unsure whether a field needs quotes, look at how the game's own data of the same kind is written and copy that.

List fields

Some fields hold several values; in JSON they're arrays:

{
  "Name": "SomeCharacter",
  "Skill": ["Slash", "Heavy Slash", "Spin Slash"]
}
Arrays replace the whole list; they don't append Written like that, the character has exactly those three skills — the originals are gone.
To keep the existing ones and add more, list the existing ones too.
Why not append: if the same patch is applied twice, appending gives ["Slash","Heavy Slash","Slash","Heavy Slash"]. Replacement is the predictable behaviour.

Comma-separated fields

Some fields are stored internally as a single comma-separated string (item Tag, for instance). Both forms work and mean the same thing:

"Tag": "Usable in battle,Fruit"
"Tag": ["Usable in battle", "Fruit"]

Example: edit an existing item

Data/Item/HerbPrice.json

{
  "Name": "Herb",
  "SellPrice": 500
}

Only the sell price changes. Nothing else is touched.

Example: add an item

Data/Item/SuperPotion.json

{
  "Name": "SuperPotion",
  "Name_I2": "Super Potion",
  "Desc": "Drink it and you get very strong",
  "Type": "Item",
  "IconName": "Potion",
  "SellPrice": 1000,
  "AddHP": 999,
  "AddMP": 99
}
IconName can borrow the game's own art Give it the name of an existing icon and that image is used. To ship your own artwork see Adding Images.

Example: make an enemy tougher

Data/Enemy/SlimeBuff.json

{
  "Name": "Slime",
  "MaxHP": "200",
  "Atk": "30"
}

Localisation

The game supports Traditional Chinese, Simplified Chinese, English, Japanese, Korean and Russian. Name and description fields ending in _I2 feed the translation system.

Omitting Name_I2 leaves the name blank Name is only an internal identifier — what players see is Name_I2. Setting only Name gives an entry with a blank name and description in game, with no error message.
Even if you're not localising, always fill in Name_I2 — just put your own language in it.
Don't end strings with punctuation The translation system treats trailing punctuation as a separator, which makes the lookup fail.
Write "Deals heavy damage", not "Deals heavy damage."
Commas mid-sentence are best replaced with a plain space as well.

Apply order

Mod data is applied at game start:

  1. The game loads its own data
  2. Mods are layered on in order (later mods override earlier ones)

Mods are always the top layer, so your changes always take effect. For conflicts between mods see Multiple Mods.

Re-enter the game from the title screen after editing Data is merged on Start New Game and Load Game. Go back to the title and enter again — no need to restart the game. A session in progress won't change.
