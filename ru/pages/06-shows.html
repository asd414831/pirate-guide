Постановки и выдача контента

Записать данные — значит лишь создать вещь. У игрока её всё ещё нет. Эта глава о том, как её действительно передать.

Именно этот шаг обычно пропускают Вы добавляете персонажа в Data/Role/, данные идеальны — и игрок его никогда не получит.
У предметов есть поле цены, поэтому они сами попадают в магазин. У персонажей и этапов такого поля нет. Выдать их можно только командой постановки.

Что такое постановка

Постановка — это список игровых команд. Это может быть сюжетный диалог или чистая работа с данными. Постановки лежат в Data/Show/, по одной на файл.

{
  "Name": "MyMod",
  "Tag": "AutoRun",
  "Shows": [
    "<AddRole>NewHero"
  ]
}
У постановки ровно четыре поля ID / Name / Tag / Shows. Поля описания нет; если его добавить, оно ничего не сделает.

AutoRun: единственная зацепка, которой мод может воспользоваться сам

Задайте Tag равным AutoRun, и постановка проиграется автоматически после «Новой игры» и после «Загрузки игры».

Data/Show/AutoRun.json

{
  "Name": "MyMod",
  "Tag": "AutoRun",
  "Shows": [
    "<AddRole>NewHero",
    "<AddItem>SuperPotion,1"
  ]
}
AutoRun выполняется каждый раз, а не один раз Он срабатывает при каждой «Новой игре» и каждой «Загрузке игры».
Обычно это безвредно — <AddRole> и <AddItem> пропускают то, что у игрока уже есть. Они не создают дубликатов и не сбрасывают уровни.

Если вам действительно нужен однократный запуск, поставьте защиту через переменную:

{
  "Name": "MyMod",
  "Tag": "AutoRun",
  "Shows": [
    "<if>{MyModInitialised}==0",
    "<AddRole>NewHero",
    "<Var>MyModInitialised,=,1",
    "<endif>"
  ]
}
В качестве Name используйте имя своего мода Name — это ключ слияния; если у двух модов постановки AutoRun названы одинаково, более поздняя молча перезапишет более раннюю. Имя мода избавляет от таких столкновений.
Tag проверяется на «содержит», а не на равенство "Tag": "AutoRun,Story" тоже считается AutoRun. Регистр не важен, поэтому autorun тоже работает.

Выдача персонажа

<AddRole>NewHero

Аргумент — это Name персонажа из таблицы данных (а не Name_I2).

Ещё два условия для галереи команды
  • ID больше 0
  • Name не пустое
Без них персонаж останется невидимым даже после выполнения <AddRole>.

Выдача этапа

Нужны обе строки.

<AddStageGroup>Mods
<AddStage>Abyss Trial
Без <AddStageGroup> этап невидим Этапы должны крепиться к группе. Нет группы — нет места для этапа в меню этапов.
В игре есть встроенная группа Mods, которую можно использовать напрямую.
Повторный запуск безопасен Группы и этапы, которые у игрока уже есть, второй раз не добавляются.

Выдача предметов

<AddItem>SuperPotion,1
Предметам обычно AutoRun не нужен Задайте SellPrice, и предмет появится в магазине, где игрок сможет его купить. <AddItem> нужен только для прямой выдачи.

Одна оговорка про AutoRun

Если сохранение прервано на середине сюжета, AutoRun выполняется параллельно с ним Загрузка сохранения, продолжающего заставку, означает, что AutoRun борется с ней за экран.
Держите в AutoRun только команды работы с данными — <AddRole>, <AddItem>, <AddStage>, <Var>.
Для диалогов и темпа лучше подходит постановка победы на этапе (см. следующую главу).
Постановки AutoRun разных модов выполняются одна за другой Никогда одновременно. Порядок — это порядок в списке модов (сверху вниз).
Поэтому <Wait> в вашем AutoRun работает как задумано — никакой другой мод не вмешается.

Соглашения об именах: как занять готовые слоты постановок

Разные части игры ищут постановки по фиксированному имени. Назовите свою постановку так же, и она будет вызвана — Tag не нужен.

Диалог персонажа на главном экране

Проигрывается, когда игрок нажимает на портрет персонажа на главном экране:

RoomTalk_<Name персонажа>

Для персонажа, у которого Name равно NewHero:

Data/Show/RoomTalk.json

{
  "Name": "RoomTalk_NewHero",
  "Shows": [
    "<Var>RoomTalkCount,+,1",
    "<if>{RoomTalkCount}>3",
    "<Var>RoomTalkCount,=,1",
    "<endif>",
    "<if>{RoomTalkCount}==1",
    "<MateImage>NewHero",
    "<MateTalk>{CurrentHomeCharacterName}: Привет.",
    "<elseif>{RoomTalkCount}==2",
    "<MateTalk>{CurrentHomeCharacterName}: Опять ты.",
    "<elseif>",
    "<MateTalk>{CurrentHomeCharacterName}: Хватит меня тыкать.",
    "<endif>"
  ]
}
Пропустить это не ошибка Персонаж просто будет молча стоять на главном экране. Добавьте постановку, если хотите реакций.
Обратите внимание: используется Name из таблицы данных, а не переведённое отображаемое имя.

Соглашения о диалогах

Записывайте говорящего в виде «Имя: текст»:

<Talk>NewHero: Доброе утро.
Имя, совпавшее с персонажем, автоматически окрашивается и подсвечивается Сверяется с Name из таблицы данных. Если совпадения нет, это просто обычный текст — не ошибка.

Как открыть и закрыть сюжетный фрагмент

Следуйте соглашению самой игры:

<BG>MyBG,0,#00000000      задать фон, полностью прозрачный
<BG>MyBG,1,#FFFFFF        проявить за 1 секунду
<Talk>Кто-то: Первая реплика.
<Talk>                     закрыть окно диалога
<Image>                    убрать портреты
<BG>,1                     плавно убрать фон

Контрольный список

Персонаж или этап добавлены, но игрок их не видит:

  1. Вы написали постановку AutoRun? (самая частая причина)
  2. Tag содержит AutoRun?
  3. Аргумент <AddRole> — это Name из таблицы данных? (а не Name_I2)
  4. ID больше 0?
  5. Для этапов: вы добавили <AddStageGroup>?
  6. Вы вернулись на главный экран и начали новую игру или загрузили сохранение?
