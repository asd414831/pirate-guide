Правка данных игры

Главное, чем занимаются моды. Менять существующие значения или добавлять совершенно новое содержимое.

Базовое правило

Mods/<ваш мод>/Data/<таблица>/<любое имя файла>.json
  • Имя папки выбирает таблицу — Data/Item/ правит предметы, Data/Role/ — персонажей
  • Один файл JSON — одна запись — один предмет на файл; не упаковывайте несколько в один файл
  • Имя файла не важно — игра читает поле Name внутри. Имя файла нужно только вам самим
Работают и Item, и TheItem Внутреннее имя таблицы — TheItem; если папка называется Item, игра сама подставит The. Принимаются оба написания — одной возможностью ошибиться меньше.

Правила слияния (самое важное)

У игры уже есть полный набор данных. Ваш JSON накладывается сверху, а не заменяет его. Ключ для сопоставления — поле Name:

Ваше NameРезультат
такое имя уже есть в игре Запись правится на месте. Меняются только те поля, которые вы указали; всё остальное сохраняет исходные значения
такого имени нет Добавляется как новая запись в конец списка
Пишите только те поля, которые хотите изменить Чтобы предмет продавался дороже, весь файл — две строки:
{ "Name": "Herb", "SellPrice": 500 }
Всё остальное (название, иконка, эффект) не тронуто.
Удаления не существует Моды не могут убрать существующее содержимое игры. Чтобы что-то не появлялось, задайте UnlockCon с условием, которое никогда не выполнится — не пытайтесь это удалить.

Name — это удостоверение

Опечатка в Name превращает правку в добавление Если вы хотели изменить «Herb», а написали «Herbb», игра не возразит — она решит, что вы хотите добавить новый предмет «Herbb». Итог: исходный Herb не изменился, зато появился странный новый предмет.
Когда мод ничего не делает, сначала проверьте Name на опечатки (включая лишние пробелы и полноширинные символы).

Как узнать имена полей

Имена полей должны точно совпадать с внутренними, включая регистр. Надёжнее всего смотреть их в просмотре таблиц данных в редакторе постановок (см. Редактор постановок): там перечислены все поля всех таблиц.

Или просто сделайте опечатку намеренно Если поля с таким именем нет, игра печатает подсказку:
TheItem has no field "IconImage", skipped. Did you mean "IconName"?
Быстрее, чем искать.

Для добавления нужен ID

У новых записей ID должен быть больше 0, иначе они пропускаются Записи с ID 0 или отрицательным считаются служебными строками-заготовками таблицы и в игре никогда не появляются.
Берите 9000 и выше, чтобы не столкнуться с содержимым, которое игра может добавить позже.
При правке существующей записи ID вообще не нужен — исходный сохраняется.

Типы: когда нужны кавычки

В JSON числа и текст записываются по-разному, и это должно совпадать с типом поля в игре.

{
  "Name": "SuperPotion",
  "SellPrice": 500,           число, без кавычек
  "AddHP": 999,               число, без кавычек
  "Name_I2": "Супер-зелье",   текст, в кавычках
  "Atk": "20"                 текст, в кавычках (см. ниже)
}
Поля характеристик снаряжения — это текст, а не числа Atk / MaxHP / AtkPercent и подобные хранят строки-формулы, поэтому пишите "Atk": "20", а не "Atk": 20.
Именно это позволяет характеристикам расти с уровнем. Если не уверены, нужны ли кавычки, посмотрите, как записаны такие же данные у самой игры, и повторите.

Поля-списки

Некоторые поля хранят несколько значений; в JSON это массивы:

{
  "Name": "SomeCharacter",
  "Skill": ["Slash", "Heavy Slash", "Spin Slash"]
}
Массив заменяет весь список, а не дописывает в конец В такой записи у персонажа будут ровно эти три навыка — исходные исчезнут.
Чтобы сохранить прежние и добавить новые, перечислите и прежние тоже.
Почему не дописывание: если один и тот же патч применить дважды, получится ["Slash","Heavy Slash","Slash","Heavy Slash"]. Замена — предсказуемое поведение.

Поля через запятую

Некоторые поля внутри хранятся одной строкой через запятую (например Tag у предметов). Обе формы работают и означают одно и то же:

"Tag": "Можно применить в бою,Фрукт"
"Tag": ["Можно применить в бою", "Фрукт"]

Пример: изменить существующий предмет

Data/Item/HerbPrice.json

{
  "Name": "Herb",
  "SellPrice": 500
}

Меняется только цена продажи. Больше ничего не затрагивается.

Пример: добавить предмет

Data/Item/SuperPotion.json

{
  "Name": "SuperPotion",
  "Name_I2": "Супер-зелье",
  "Desc": "Выпей — и станешь очень сильным",
  "Type": "Item",
  "IconName": "Potion",
  "SellPrice": 1000,
  "AddHP": 999,
  "AddMP": 99
}
IconName может брать графику самой игры Укажите имя существующей иконки, и будет использовано это изображение. О том, как подключить свою графику, читайте в главе Добавление изображений.

Пример: сделать врага крепче

Data/Enemy/SlimeBuff.json

{
  "Name": "Slime",
  "MaxHP": "200",
  "Atk": "30"
}

Локализация

Игра поддерживает традиционный китайский, упрощённый китайский, английский, японский, корейский и русский. Поля названий и описаний, оканчивающиеся на _I2, передаются системе перевода.

Без Name_I2 название останется пустым Name — это только внутренний идентификатор. Игрок видит Name_I2. Если задать лишь Name, в игре получится запись с пустым названием и описанием, причём без сообщения об ошибке.
Даже если вы не делаете локализацию, всегда заполняйте Name_I2 — просто напишите туда текст на своём языке.
Не заканчивайте строки знаком препинания Система перевода считает конечный знак препинания разделителем, из-за чего поиск перевода не находит строку.
Пишите "Наносит тяжёлый урон", а не "Наносит тяжёлый урон."
Запятые внутри предложения тоже лучше заменять обычным пробелом.

Порядок применения

Данные модов применяются при входе в игру:

  1. Игра загружает свои данные
  2. Моды накладываются по порядку (более поздние переопределяют более ранние)

Моды всегда верхний слой, поэтому ваши изменения всегда срабатывают. О конфликтах между модами читайте в главе Несколько модов вместе.

После правки войдите в игру заново с главного экрана Данные объединяются при Новой игре и Загрузке игры. Вернитесь на главный экран и войдите снова — перезапускать игру не нужно. Уже начатая сессия не изменится.
